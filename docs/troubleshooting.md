# 排障

先运行 `cpet --version` 和 `cpet status`。提交 issue 前去掉任务 ID、私人目录、凭据与对话内容。

## 任务列表有任务，宠物却不显示

1. 使用安装更新后重新启动的 `cx`；运行中的旧转接器不会热更新。
2. 首次配置时已运行的桌面应用需要在任务结束后退出，再用 `cpet on` 打开。
3. 查看最近订阅状态：`subscription_confirmed` 是日志确认，`opened_unconfirmed` 是已打开但尚未确认，`open_failed` 是打开失败。
4. 确认宠物已启用、活动气泡已展开、任务没有静音。
5. 选择正在运行、等待处理、失败或有未读回复的任务验证；已读空闲任务可能不显示。

日志确认不等于肉眼确认气泡。若仍失败，请记录应用版本及最小步骤。

## 桌面已经回答，CLI 还显示待回答

`0.1.0-alpha.2` 默认适配连接后收到的实时异步提问，不需要修改官方 CLI。

1. 更新源码并运行 `./install.sh`，确认 `cpet --version` 为 `0.1.0-alpha.2` 或后续版本。
2. 结束当前工作后退出旧 `cx`，用 `cx resume --all` 恢复。旧转接器和已经显示的原生提问框不会热更新。
3. 用恢复之后产生的新问题检查：桌面提交答案后，CLI 的对应提问框应关闭；多个问题逐个匹配。
4. 历史里未答的问题在桌面回答。适配器不根据不完整的历史分页猜测哪些问题仍需弹框。

标准 CLI 提问框与原生异步控件外观不同，`Esc` 会按界面提示中断。要恢复原始行为，可运行 `CPET_QUESTION_SYNC=0 cx resume --all`。版本不兼容时请报告应用及内置 CLI 的准确版本。

## 提示 “cpet could not confirm this answer”

后台拒绝、连接失败或 15 秒内未确认时，cpet 不会重试该答案。请先到桌面查看答案是否已经收到，再决定是否需要重答。任务刚好结束时，`turn/steer` 也可能被拒绝；不要连续点击提交。两端完全同时回答同一问题仍可能产生两份消息，建议在一端提交后等待另一端更新。

## 每次输入都切换到桌面

正常情况下仅首次订阅/恢复才需要打开任务。先确认已经安装最新版且重启了 `cx`。如果状态反复是 `opened_unconfirmed`，可能是日志格式不兼容、桌面连接未生效或反复失效；请提交脱敏片段，不要通过重复开关后台强行恢复正在执行的任务。

## `no rollout found for thread id ...`

历史修复：临时（ephemeral）会话没有可恢复的持久化记录，旧转接器曾在其 `turn/start` 时错误打开桌面。当前版本会在创建和后续执行两个阶段过滤它们。

确认更新并重启 `cx`。如果错误仍针对普通持久任务出现，可能有任务记录缺失或后台/数据目录不一致，应单独排查；不要删除数据库或把临时任务 ID 当成可恢复历史任务。

## `invalid remote address`

CLI 的远程地址应是 `ws://host:port`，不应带凭据路径。cpet 使用随机 Bearer 凭据和 `--remote-auth-token-env`；请用安装后的 `cx`，不要复制旧的临时地址或令牌。

## 端口 4500 被占用

先检查占用者：

```sh
lsof -nP -iTCP:4500 -sTCP:LISTEN
```

cpet 不会终止不属于它的服务。确认进程用途后再决定处理，不要直接 `kill -9`。

## 访问文稿目录失败，或桌面工具不可用

launchd 进程的 macOS 隐私授权和环境不等于终端或桌面内置后台。共享后台也可能缺少桌面专用工具管道。优先在普通测试目录验证；按 macOS 系统设置检查适用的文件访问授权，不要绕过应用的权限检查。需要完整桌面工具能力时，结束任务后 `cpet disable`、`cpet off`，退出并重新打开桌面，恢复其原后台。

## 移动源码之后命令失效

`0.1.0-alpha.1` 的安装器已将运行副本与源码分离。如果 `~/.local/bin/codex-pet` 仍指向旧源码路径，重新执行新源码中的 `./install.sh` 完成迁移。独立 `.venv` 仍依赖创建它的 Python 解释器；卸载该解释器后需要用可用 Python 重建运行环境。

## 日志位置

`~/Library/Application Support/Codex CLI Bridge/` 下：

- `server.stderr.log`：共享后台错误。
- `desktop-relay.stderr.log`：转接错误。
- `login.stdout.log` / `login.stderr.log`：登录启动日志。
- `attachments/`：最近订阅诊断，仅用于状态展示，不作为持久订阅凭证。

桌面原生日志位于 `~/Library/Logs/com.openai.codex/`；字段随版本变化。不要把整个日志目录上传到公开 issue。
